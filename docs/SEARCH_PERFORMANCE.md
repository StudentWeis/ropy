# 搜索基准与优化方案

## 目标与边界

本次工作优化剪贴板历史的单查询串搜索。匹配结果、源记录索引、显示排序、大小写选项、全词选项、类型筛选和收藏筛选保持原有语义。性能结论必须来自同一机器、同一固定数据集和同一计时边界的前后比较。

搜索只处理当前已加载的历史记录，默认上限为 100 条，允许配置到 10,000 条。基准额外覆盖 1,000 和 10,000 条以观察增长趋势。数据库读取、显示排序、GPUI 通知、布局、绘制和键盘到屏幕的延迟不在本次过滤基准内，不能用过滤耗时替代端到端交互延迟。

## 现状与代码边界

原实现位于 `src/gui/board/search.rs`：逐条记录做筛选，不区分大小写时为每条正文和查询串分配小写字符串，全词模式逐字符检查前缀，文件记录先反序列化再按路径搜索。

先将纯筛选迁移到 `crates/ropy-core/src/search.rs`，保留算法和原有测试作为基线。桌面搜索栏通过重导出调用同一个入口，基准直接调用 `filter_records_by_query`。界面继续拥有搜索输入、选项、显示排序和选择状态；核心模块接收不可变记录切片，只返回源索引，不持有跨查询状态。

## 必须保留的匹配契约

- 默认匹配连续子串，不引入模糊搜索、分词、多关键词语法或正则表达式。
- 不区分大小写时沿用 Rust `str::to_lowercase`，包括 `İ` 的多字符展开和希腊词尾 sigma 的上下文规则。不改为 ASCII-only 比较、逐字符小写转换或完整 Unicode case folding，也不增加规范化；`Straße` 与 `STRASSE`、组合形式与预组字符仍可不匹配。
- 全词边界仍以 Unicode 字母、数字和下划线定义。中文连续字串不是自然语言分词。边界按小写转换后的正文检查。
- 全词候选必须保留重叠，例如在 `xa-a-a` 中查询 `a-a`，第一个候选左边界不合法，后一个候选合法。不能直接用跳过重叠的迭代器。
- 文件路径沿用 `deserialize_file_paths`：JSON 转义、文件 URI 解码、普通文件名中的百分号、空路径过滤、旧版单路径和无效 JSON 回退行为都保留。不能直接搜索序列化 JSON，也不能跨路径匹配。
- 类型和收藏筛选在文本处理前执行。图片筛选忽略查询；其他筛选在查询非空时排除图片。空查询不触发文本或路径解析。
- 结果保持输入顺序和源索引；更新或删除源记录后再次查询必须读取当前内容。

## 基准设计

复用已有 Criterion 0.8.2 和 release 优化配置，新增独立的 `search` benchmark，不改变存储和 RSS 基准的 v1 定义。数据不读取真实剪贴板，不使用随机数，时间戳固定，正文由索引和固定模板生成。

| 场景 | 数据与查询 | 保护的性能路径 |
| --- | --- | --- |
| ASCII 命中、未命中 | 约 1 KiB，10% 尾部命中或完全未命中 | 默认搜索的全文扫描和分配 |
| 区分大小写、前缀查询 | 相同数据，查询 `Needle42` 或 `need` | 避免破坏无需小写转换的路径 |
| 全词、区分大小写全词 | 相同数据，10% 合法匹配 | 候选搜索和边界校验 |
| 密集非法全词 | 大量 `needle42_x`，10% 记录有合法尾部匹配 | 不合法候选多时的成本 |
| Unicode 命中、未命中、全词 | 中文、重音字符、希腊文、大小写展开和 emoji | 保留 Unicode 语义的路径 |
| JSON 文件列表 | 每条三条路径，10% URI 解码后命中 | 解析、解码和多个路径搜索 |
| 旧版单路径 | 普通路径与文件 URI | 兼容分支 |
| 空查询、图片、收藏 | 空查询全选、图片忽略查询、5% 收藏 | 提前筛选、结果索引分配 |
| 长文本 | 100 条约 72 KiB，10% 尾部全词命中 | 大剪贴板负载 |
| 长公共前缀 | 100 条 64 KiB 重复字符，32 字节查询未命中 | 逐位置比较的退化情况 |

前十五类场景分别使用 100、1,000、10,000 条记录，共 45 组；两组长文本单独使用 100 条。普通文本中交替包含 Text 和 RichText。每组正式计时前用独立生成的预期索引断言结果，防止把漏搜或空结果当成优化。

计时包含每次调用的查询准备、正文处理、文件解析、边界检查、结果向量分配和释放。数据生成、预期检查、收藏集合构造和读取磁盘均在计时外。用 `black_box` 保留实际工作，不在循环外预编译查询。每组预热 500 ms，采集 30 个统计样本，目标测量 1 秒。报告 Criterion 中位数及其 95% 置信区间；这不是请求 P95。每秒记录数只表示处理输入记录的速度，不等于读取字节吞吐量。

## 比较方案与实施顺序

1. 建立行为基线。先增加独立核心 API 契约测试，确认旧模块无法提供新接口；迁移现有实现和测试后运行通过。提交基准入口后测量未优化版本并保存原始样本。
2. 减少重复准备。将查询的小写转换移到记录循环外；仅为候选记录进行正文转换。保留 Unicode 标准库转换，先不维护正文缓存。
3. 比较单模式搜索器。评估一次查询内复用 [`memchr::memmem::Finder`](https://docs.rs/memchr/2.8.3/memchr/memmem/struct.Finder.html)，全词模式只在找到候选后检查边界。失败后推进到候选后的下一个 UTF-8 字符边界，保留重叠候选。与直接使用标准库 `contains`/`find` 比较收益和依赖成本。
4. 根据测量决定额外优化。只有文件解析、正文小写或筛选后的排序仍成为实际瓶颈时，才进一步设计缓存或增量处理；不能根据总耗时推断某个分配已经占主要比例。
5. 同机复测并归档。通过完整 precheck 后提交最终实现，在干净提交上运行相同基准。保存前后提交、系统与编译器信息、基准源码摘要、原始样本和统计结果，再提交结果文档。

| 候选 | 收益与代价 | 本次决策依据 |
| --- | --- | --- |
| 每次查询准备一次，单模式扫描 | 不引入跨查询状态，直接减少重复工作 | 优先实现并用基准确认 |
| Aho–Corasick | 适合一组固定关键词的多模式匹配；本项目当前只有一个查询串 | 暂不引入；多关键词需求出现后重新评估 |
| 正文小写与路径缓存 | 可减少重复转换，但增加内存、更新和删除失效规则 | 需要额外测量证明收益；本轮先保持无缓存 |
| 后缀自动机或全文索引 | 可复用文本索引，但需要记录归属、动态删除、重建和内存管理 | 当前范围不引入 |
| 后台任务或输入防抖 | 能降低界面阻塞，但增加过期结果处理或可见等待 | 仅在实际交互延迟超标时单独设计 |

## 验证与接受标准

正确性优先于性能：核心单元测试、公共 API 契约测试、桌面筛选/搜索交互测试及完整 `scripts/precheck.sh` 均须通过。纯匹配重构不涉及原生剪贴板和窗口行为，不将无桌面基准解释为跨平台 GUI 验收。

性能以同机中位数和置信区间判断，不对 CI 设置容易受共享运行器噪声影响的时间断言。默认 100 条和压力数据都要报告；只有大数据或特制负载加速不能证明默认体验改善。重点检查全词与长文本场景，默认 ASCII、Unicode、文件和筛选路径不能出现未经解释的明显退化。低于微秒量级的绝对差异单独说明。若新搜索器有稳定回退，调整策略或撤回该部分，不用单个最好结果代表全部数据。

本轮不保留跨查询正文副本，因而无新增常驻正文缓存。查询辅助结构与临时字符串在调用结束释放；内存复杂度按最长候选正文、查询和输出索引计算。算法层面推导不代替 RSS 测量，本套基准没有测量进程峰值内存或分配次数。

## 选定实现

采用每次过滤只小写化一次查询，并构建一个借用该查询的 `memmem::Finder`。所有记录和文件路径共用这个搜索器。普通子串直接判断是否存在匹配；全词模式在候选位置检查原有边界，失败后使用 `ceil_char_boundary(start + 1)` 继续查找。空查询和图片筛选不创建搜索器，图片筛选也不转换查询串。

标准库原型同样减少了查询转换，并把逐字符探测改为反复 `str::find`。它在 100 条记录的普通全词场景从约 178 微秒降到 14 微秒，但密集非法候选从约 183 微秒升到 232 微秒。复用 Finder 后，这两类场景分别约为 7 和 60 微秒，因此保留 Finder 方案。原型只用于方案选择，正式结果以最终干净提交的再次测量为准。

`memchr` 2.8.3 原本已在锁文件中；本次只增加核心模块的直接依赖，不引入新的包或版本。正文仍使用标准库的完整小写转换，文件仍使用原有路径解码器。没有持久化格式变化、索引构建、缓存失效规则、额外线程或新的界面选项。

Finder 的单次子串查找有线性时间保证，但这里的全词模式可能多次查找重叠候选，不能据此宣称整个全词算法在所有输入上都只扫描一次。密集候选和长公共前缀场景用于监测这部分成本。Unicode 子串场景不承诺明显改善；首次候选测量出现的默认 Unicode 波动在交替复测中没有重现，须同时保留原始结果与复测证据。

## 复跑命令

使用仓库固定 Rust 工具链，停止构建和其他高负载工作，在一致的电源模式下单独运行。Criterion 默认输出在 `target/criterion/search_v1/`；基准名称不能跨不同数据或计时定义直接比较。

```sh
make bench-search SEARCH_BENCH_ARGS='--save-baseline search-before'
# 切换到待比较实现，并保留同一份 target/criterion 目录。
make bench-search SEARCH_BENCH_ARGS='--baseline search-before'
# 只复跑一组场景；过滤器仍由 Criterion 处理。
make bench-search SEARCH_BENCH_ARGS='whole_word --baseline search-before'
cargo test --locked -p ropy-core search
./scripts/precheck.sh
```

最终结果与具体方案取舍在完成同机测量后记录于本文，并将原始数据归档到 `docs/benchmarks/search/`。
