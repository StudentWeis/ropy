# 核验与审查

## Ropy 检查入口

命令从仓库根目录执行，前置条件见[开发指南](../../../../docs/development.md)。

- `git diff --check`：检查差异空白；另行阅读新文件和检查 Markdown 标题、围栏、链接与资源。
- `make help`：核对公开 Make 入口，不启动桌面应用。
- `python3 scripts/check/check_i18n.py` 与 `python3 scripts/check/check_themes.py`：检查语言和主题资源契约，不证明视觉效果。
- `./scripts/precheck.sh`：提交前完整门禁。只做快速诊断可先用 `./scripts/precheck.sh --check --light`，但不能把它当作完整通过。
- `cargo test --locked -p ropy-core`：验证便携核心，不能证明原生剪贴板、窗口或桌面适配行为。

当前没有仓库内 Markdown 专用校验器。使用外部 Markdown 工具时报告工具与范围，不把个人环境写成所有贡献者的前置依赖。检查历史/生成文档时保留其格式和数值；官方 GPUI 快照按 ropy-gpui 的上游比较程序验证，不批量修复。

## 核验示例

- 改写快捷键说明：查 `src/gui/board/actions/shortcuts.rs`、`crates/ropy-core/src/config/settings.rs` 和相关测试；核对替换、禁用、冲突及恢复行为，再同步 README 的入口说明，不复制整张键表。
- 新增用户配置页：先确认配置路径与恢复保护的实现，只写读者需要的编辑和恢复步骤，将主题和快捷键细节链接到已有页面。新页面加入索引，中英文入口同步链接。
- 整理 Wayland 或 Windows 回归：保留 compositor、平台、来源提交和未验收边界。没有隔离桌面时只能报告静态核验，不运行正常应用去借用用户的剪贴板。
- 整理性能报告：比对关联 JSON 和测量提交；历史报告通过不等于本次重新运行。不要为了格式化重写生成结果。

## 按声明选择证据

先确认仓库实际提供的文件、命令与环境，再选择验证方式。文档提到某个工具，不代表它已经安装或接入。

| 声明 | 核验方式 |
| --- | --- |
| 当前接口、字段与默认值 | 查实现、schema、配置定义及相关测试；行为示例另行执行 |
| 命令、配置与快速上手 | 在可用且安全的环境按最终文档原样执行，确认工作目录、前置条件与结果 |
| 错误、并发、取消与恢复 | 查对应测试或复现关键路径，说明实际覆盖范围 |
| 外部系统能力 | 查可访问的权威契约，按需联调；本地 fake 不证明真实上游行为 |
| 拟议设计 | 查决策来源、约束与验收方法，保留未验证状态 |
| 历史决策 | 核对日期、当时依据与后继记录，不改写为当前实现 |

执行需要真实凭证、远端修改、破坏性操作或费用时，遵守任务授权范围。先完成安全可做的核验；环境、权限或依赖不足时，报告未验证项、所缺条件和后续验证方式，不编造运行结果。示例不得包含真实凭证或敏感输出。

无法复现的既有声明应查明条件差异，再纠正、删除或标为未验证；不直接断言它正确或错误。没有实现时检查设计一致性与链接，不伪造服务、构建或联调成功。

## 适用检查

1. 按项目约定核对结构、元数据、链接、锚点、资源与代码块；移动或更名时搜索旧路径，修复受影响的入站引用。
2. 运行实际存在的相关文档检查。行为声明变化时选择能覆盖对应风险的实现测试；纯排版修改不要求全量构建与测试。
3. 只有存在重复需求时才新增校验器，并证明它能区分合法与非法输入。不为通过检查删掉必要契约或放宽规则。
4. 项目有生成流程时确认编辑来源与输出目录，只修改来源并运行相应生成与预览检查。构建通过不代表内容正确或已部署。
5. Git 仓库执行 `git diff --check` 并通读完整差异；未跟踪的新文件另行阅读检查，不能因为普通 diff 未显示而遗漏。其他版本管理方式使用其适用检查。

缺少自动检查时明确手动核验范围，不为本次写作虚构工具入口。报告实际执行的命令、结果和未覆盖的环境差异，不把静态检查通过等同于语义准确或真实使用验收。

## 内容审查

优先检查事实与任务路径，再检查结构和措辞：

- 读者能否识别适用场景、前置条件、成功状态、失败与下一步？必要风险是否在操作前可见？
- 草案、已接受设计、实现、部署和联调状态是否区分？未验证声明是否保留条件？
- 默认值、错误、权限、一致性与恢复是否有证据？本项目的关键契约是否完整？
- 每个事实是否有明确拥有者？入口和指南是否复制了字段、规则或实现细节？
- 页面是否按职责组织？压缩篇幅或拆页是否使必要边界难以发现？
- 是否混入工作过程、过期计划、宣传措辞、空泛结论或已解决的备注？

审查结果按影响列出位置、问题与建议。只修正请求范围内的内容，区分文档缺陷与需要单独处理的产品行为变化。
