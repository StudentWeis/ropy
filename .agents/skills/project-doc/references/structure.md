# 文档组织

Ropy 的页面归属和入口以[文档索引](../../../../docs/README.md)为准。文件名遵守技能入口中的命名约定，不为套用分类增加目录。路径调整必须同步引用，不保留两份内容相同的权威页面。

## Ropy 的维护边界

- README 帮助用户判断平台是否适用、安装和开始使用；开发工具与命令由 `docs/development.md` 拥有，不在两个 README 复制。
- `CONTRIBUTING.md` 及其中文入口说明如何贡献资源和找到流程；Issue、分支、提交和 PR 命令由 contribution-flow 拥有，发布顺序由 `docs/releasing.md` 拥有。
- 配置路径、编辑注意事项与加载失败恢复由 `docs/configuration.md` 拥有；快捷键和主题指南只维护各自的操作、覆盖、错误与回退契约。
- 架构说明维护跨模块职责与一致性边界。测试指南串联检查与证据，不能复制完整实现或把历史测试数量当作当前基线。
- `docs/benchmarks/` 保存历史证据，不是待办目录。正文说明测量边界和来源提交，生成结果不手改；新的设计状态不回写到旧测量值中。
- GPUI 官方技能不是本项目文档整理的格式化对象。Ropy 的差异留在 ropy-gpui，其他项目级技能按各自职责维护。

## 按职责选择位置

先使用 `SKILL.md` 中记录的项目入口与归属，不把本表转换成必须创建的目录。一个页面解决一个主要读者任务，同一事实只在一个位置维护，其他页面通过链接引用。

| 类型 | 读者任务 | 建议主体顺序 |
| --- | --- | --- |
| 概览 | 判断项目或能力是否适用 | 能力与边界 → 当前状态 → 最短入门路径 → 导航 |
| 操作指南 | 完成一项具体任务 | 前置条件 → 步骤 → 成功判据 → 常见失败与恢复 → 可选进阶 |
| 架构说明 | 理解系统如何协作 | 问题与边界 → 组件职责 → 数据流与生命周期 → 一致性与失败 → 关键取舍 → 实现入口 |
| 模块参考 | 使用或修改一个模块 | 能力与边界 → 调用入口 → 配置与契约 → 设计说明 → 限制 → 源码与测试入口 |
| 接口参考 | 正确调用接口 | 适用范围 → 权限与前置条件 → 输入输出 → 错误 → 并发、幂等或取消语义 → 示例 |
| 设计方案 | 评估尚未落地的方案 | 状态与已确认范围 → 问题和目标 → 约束与非目标 → 提议 → 取舍 → 失败与恢复 → 验收方法 → 未决问题 |
| 决策记录 | 追溯一项选择 | 日期与状态 → 背景 → 决策 → 备选及理由 → 影响与代价 → 替代关系 |

按实际内容保留章节，不填空壳，不要求每类都有页面。运行与排障通常属于操作指南；生成参考遵循生成器格式，不强加手写骨架。

## 层次、范围与状态

读者需要分层理解设计时，区分目标与范围、模块协作、具体实现契约。精确规则由最合适的页面拥有，上下层通过链接关联；不强制三层目录，也不在每层复制同一套页面。

层次不表示交付范围或实现状态。深层实现设计仍可能是草案，已接受架构仍可能尚未实现。混合已确认选择与拟议细节时，在页面和相应段落中明确边界，不能让局部确认看起来像全篇已实现。

## 入口、元数据与导航

入口说明直接子页面各解决什么问题，不重复正文。目录变大、检索出现实际困难后再增加索引，不预建空目录或页面。

沿用项目已有元数据和状态约定。若确有新增分类或检索需求，先确定字段用途与维护者；编辑约定不能写成已经存在的自动检查能力。标题应稳定、具体，改名时同步更新引用。

迁移前查找入站链接，迁移时修复正文、资源、索引与已有路由。只有实际存在且仍有消费者的公开地址或别名才需要兼容处理，不假定项目已有网站。
